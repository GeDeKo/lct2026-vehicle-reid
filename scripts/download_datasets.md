# Готовые датасеты для re-id и атрибутов

Готовые датасеты приоритетнее парсинга — в них снимки с настоящих камер
наблюдения, а не студийные фото с сайтов объявлений. Парсинг (см.
`parse_drom.py`) — источник для атрибутов (марка/модель/цвет/кузов) и
дополнительных положительных пар.

## Re-ID (снимки с камер, для обучения и baseline-оценки)

| Датасет | Как получить | Заметки |
| --- | --- | --- |
| **VeRi-776** | Форма запроса у авторов: https://github.com/JDAI-CV/VeRidataset | Основной бенчмарк, ~50 тыс. фото, 776 машин. Ответ обычно приходит не мгновенно — запросить в первую очередь, в день старта. |
| **VehicleID** | Форма запроса: https://pkuml.org/resources/pku-vehicleid.html | ~200 тыс. фото. |
| **VeRi-Wild** | https://github.com/PKU-IMRE/VeRi-Wild | ~416 тыс. фото, разные условия съёмки. |
| **CityFlow-ReID (AI City Challenge)** | https://www.aicitychallenge.org/ (нужна регистрация) | Городские камеры, ближе всего к задаче. |
| **BoxCars116k** | Без регистрации, бэкап на Google Drive (см. ниже) | **116k фото, 27 496 размеченных треков (одна и та же машина с разных ракурсов), 693 модели, 137 реальных камер видеонаблюдения.** Единственный из списка, который можно скачать прямо сейчас без формы/ожидания. Проверено вживую (сентябрь 2026). |

Если к моменту старта доступ ещё не пришёл — не блокируемся: строим baseline
на BoxCars116k (доступен сразу) и на уже скачанном, а как только приходят
остальные — пересчитываем метрики.

### BoxCars116k — как скачать

Официальная ссылка с сайта VUT Brno (`medusa.fit.vutbr.cz`) на момент проверки
не резолвилась (сервер, похоже, недоступен/переехал). Рабочий бэкап — Google
Drive, публичный, без логина:

```bash
FILE_ID="19LHLOmmVyUS1R4ypwByfrV8KQWnz2GDT"   # id файла BoxCars116k.zip на Google Drive
# архив ~6.0 ГБ — проверьте, что на диске есть 15+ ГБ свободных (архив + распаковка)
pip install gdown
gdown "$FILE_ID" -O data/raw/boxcars116k.zip
unzip data/raw/boxcars116k.zip -d data/raw/boxcars116k
```

Структура: изображения + JSON с разметкой (vehicle track id, модель, ракурс).
Формат разметки не совпадает 1:1 с VeRi-776 — под `eval_reid.py` нужен
небольшой скрипт-конвертер (сгруппировать фото по `track_id`, разложить в
`query/`+`gallery/` как `<track_id>_c<camera_id>_*.jpg`), это отдельная
задача при подключении датасета.

## Атрибуты (марка, модель, кузов)

| Датасет | Как получить | Заметки |
| --- | --- | --- |
| **Stanford Cars** | `torchvision.datasets.StanfordCars` (скачивается автоматически) или Kaggle: https://www.kaggle.com/datasets/jessicali9530/stanford-cars-dataset | 196 классов марка+модель+год, американский рынок. |
| **CompCars** | Форма запроса: http://mmlab.ie.cuhk.edu.hk/datasets/comp_cars/ | Крупный датасет марок/моделей, азиатский+западный рынок. |
| **Drom.ru / Avito Авто (свой парсинг)** | `python scripts/parse_drom.py --brand <марка> --model <модель>` | Российский рынок, точные метки, несколько фото на объявление = пары для re-id. См. предупреждения в самом скрипте. |

## Быстрый старт с своим парсингом

```bash
# один запуск = одна пара марка/модель, объявления идут не спеша (rate-limit внутри)
python scripts/parse_drom.py --brand toyota --model camry --max-ads 200 --max-pages 20

# повторить для нужных марок/моделей — списком в shell-цикле, тоже не спеша:
for pair in "toyota camry" "kia rio" "hyundai solaris" "lada vesta" "volkswagen polo"; do
  set -- $pair
  python scripts/parse_drom.py --brand "$1" --model "$2" --max-ads 150
done
```

Из `metadata.jsonl` дальше собирается train/val сплит для голов атрибутов
(`brand`, `model`, `body_type`, `color`) и, если нужно, пары для re-id
(фото из одного `ad_id` — одна и та же машина).

## Разрыв доменов: Drom-фото ≠ кадры камер

Фото объявлений — студийные/уличные, чистые, высокое разрешение. Кадры
городских камер — низкое разрешение, ночь, сжатие, ракурс сверху. Без
компенсации модель, обученная только на Drom, может плохо перенестись на
реальные камеры. Два способа закрыть разрыв, оба уже готовы:

1. **BoxCars116k** (выше) — реальные камеры, самый надёжный вариант.
2. **`scripts/camera_augment.py`** — дешёвая имитация камеры поверх уже
   собранных Drom-фото (blur, шум, JPEG-сжатие, имитация ночи, лёгкая
   перспектива сверху). Не заменяет реальные данные, но быстро и без
   новых источников:

```bash
python scripts/camera_augment.py --input-dir data/raw/drom --out-dir data/processed/camera_aug --variants 3
```

Лучше всего — использовать оба вместе: BoxCars116k как основа для re-id,
Drom + camera_augment как дополнительный сигнал и источник атрибутов.
