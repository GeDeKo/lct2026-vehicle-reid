# Re-ID console — веб-демо

React + TypeScript + Vite. Сайт и API — разные origin в любом случае,
даже если бэкенд крутится у вас же на localhost.

**Два способа поднять бэкенд:**
1. **У себя на GPU** (рекомендуется для проверки) — см.
   [DOCUMENTATION.md → «Как развернуть»](../DOCUMENTATION.md#как-развернуть)
   в корне репозитория: `download_release_assets.sh` + `uvicorn`.
2. **Через наш уже поднятый A100** — ниже, нужен пароль от jump-proxy
   (передаётся отдельно, не в репозитории).

В обоих случаях сайт по умолчанию ходит на `http://localhost:8800` — само
API-бэкенд не знает и не важно, где физически крутится инференс.

## Если на показе что-то сломалось (быстрый план, способ 2)

Сейчас всё уже поднято и работает: `web/keep_tunnel_alive.sh` держит
проброс порта живым в фоне (сам переподнимает за секунды, если оборвётся),
прод-сборка раздаётся на `http://localhost:5500`. Если ноут перезагрузили
или всё-таки развалилось:

```bash
# 1. Туннель (само-восстанавливающийся, оставить работать в фоне/отдельном окне)
# пароль от jump-proxy не хранится в репозитории — его сообщают отдельно
JUMP_PASS='...' ./web/keep_tunnel_alive.sh &

# 2. Проверить API
curl http://localhost:8800/health   # ждём {"status":"ok",...}

# 3. Сайт (прод-сборка, не dev-режим — меньше что может сломаться)
cd web && npm run build && npx vite preview --port 5500
# открыть http://localhost:5500
```

Если `/health` не отвечает даже после туннеля — значит упал сам API-процесс
на A100, тут уже нужен доступ по SSH и `nohup uvicorn src.api.main:app
--host 0.0.0.0 --port 8800 > api_server.log 2>&1 &` в `~/lct2026` (venv
активировать перед этим).

## 1. Пробросить API-порт с A100 на ноут

API на сервере слушает `0.0.0.0:8800` (уже запущен в фоне). Прокинуть его
на свой `localhost:8800` через тот же jump-proxy, что и SSH:

```bash
ssh -p 40007 -fN -L 8800:172.16.2.93:8800 ansible-server@89.125.151.113
```

Проверить: `curl http://localhost:8800/health` → `{"status":"ok",...}`.

## 2. Запустить сайт

```bash
npm install
npm run dev
```

Открыть адрес, который выведет Vite (обычно http://localhost:5173).

По умолчанию страница ходит на `http://localhost:8800`. Переопределить:
скопировать `.env.example` → `.env` и поменять `VITE_API_BASE`, либо
добавить `?api=http://host:port` к адресу страницы (для быстрой проверки
без пересборки).

## Продакшн-сборка

```bash
npm run build   # dist/ — статика, можно раздать чем угодно
npm run preview
```

## Что показывает страница

Слева — захват кадра: перетаскиваешь фото машины, жмёшь «Найти похожие»
(идёт на `/identify`) или «Добавить в базу» (`/enroll`, нужен `camera_id`).
Справа — совпадения из базы: превью кропа, идентификатор камеры и
таймкод (как оверлей на самой камере), полоса уверенности. Цвет/кузов
— zero-shot CLIP, марка/модель — обученные головы, если бэкенд их отдаёт.

## Структура

```
src/
  api.ts          — запросы к API, типы ответов
  types.ts        — зеркало pydantic-моделей FastAPI
  format.ts       — форматирование времени
  components/     — Dropzone, CapturedFrame, ProfilePanel, MatchTile, BrandMark
  App.tsx         — вся логика состояния страницы
```
